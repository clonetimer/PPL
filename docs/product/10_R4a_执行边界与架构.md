# R4a 执行边界与架构

## 背景、目标与角色

R3 已提供工作台，但“配置了模型”“HTTP 返回 JSON”“治理门禁实际生效”“真实任务成功”是不同命题。R4a 收紧进入领域服务的模型输出，修复错误的配置独立性判断，让验收结果不再互相替代。本机可信操作者负责端点、模型和资料授权；应用 Agent 仍只能在既有领域权限内执行。

## 复现与修复

| 编号 | 原始 dev.4 实际复现 | R4a 修复及回归 |
|---|---|---|
| R4-001 | 同模型因默认 agent/judge 前缀产生不同 independenceGroup，可通过 required | 默认分组不含角色/端口；产品层 required 拒绝相同模型 ID、相同分组、未知身份；允许 preferred 警告 |
| R4-002 | invokeStructured 对错误 schema、字符串布尔值仍返回 ok | 解析后检查项目持有的完整响应契约；Agent 无工具调用的分支也检查；失败不进入后续领域更新 |
| R4-003 | 检索跟随 302 到另一位置 | 所有 3xx 都拒绝，包括同源；不得借重定向扩大原端点权限；测试确认目标端点收到 0 次调用 |
| R4-004 | 旧 live probe 收到语义 ok:false，退出 0 | 逐请求随机 nonce，必须返回准确 schema、布尔 true、匹配 nonce 且无额外字段 |

其他新增项：检索响应字节上限、整段响应体截止时间、请求取消、文档长度和数量限制、非空检索验收；配置的模型请求也经过有限响应边界。错误详情不回显上游 HTTP 错误正文，避免把反射的凭据复制进诊断报告。

## 执行链与应用边界

Generic Agent：合约/委派/投影 → 模型或 Host 工具 → 响应契约 → MAG fidelity → 独立 Agent execution record。

Research：有界 Retrieval → 有界文档 → Extractor 响应契约 → provisional claim → Analyst 契约与保真 → Reviewer 契约与保真 → binding → Judge 契约和身份绑定 → 原领域门禁 → 确定性交付。

Tutor、Life、Character 的数据 schema 和命令未合并，已有回归照常执行。没有为了新 qualifier 引入共享大业务对象、第二个 durable-state owner 或额外服务。

## 响应契约

支持 object/array/string/number/integer/boolean/null、required/properties/additionalProperties、enum/const、anyOf、items 及长度/数值上下界。未知关键字或不支持的 schema 定义报配置错误。实例异常只给字段路径和错误码，不回显恶意字段名或原始值。不是完整 JSON Schema 校验器；新增响应 schema 时需扩展实现和测试，不能依赖未实现关键字。

confidence 必须是 [0,1] 内的 number，不再将字符串或越界值强制转换/截断。relevant/pass 必须是 boolean。irrelevant 提取可以用空 canonicalText；relevant 主张的非空性仍由领域服务验证。结构化答复中的工具请求不能绕过工具通道。

## 配置身份与限制

同一模型 ID 即使端点/分组不同，也不能在 required 模式下算独立。不同模型但明确声明同组也不通过。preferred 继续运行但返回警告；disabled 不是资格证明。验收工具始终要求 distinct 配置身份，不依赖运行配置中的宽松选项。

不同模型 ID 可能是同一模型的别名；相同 ID 也可能是不同服务的命名碰撞。本实现保守拦截相同 ID，但不能认证服务权重、供应链或统计独立性。报告明确保留 statisticalIndependenceProven:false。

## 资源与安全边界

| 项目 | 默认值 | 允许范围/语义 |
|---|---:|---|
| PPL_HTTP_TIMEOUT_MS | 30000ms | 1..300000；单次非流式 HTTP 调用的连接至响应体读取期限 |
| PPL_HTTP_MAX_RESPONSE_BYTES | 2097152 | 1..16777216；实际读到的解压后响应字节数也检查 |
| PPL_RETRIEVAL_MAX_DOCUMENT_CHARS | 50000 | 1..200000；超限拒绝，不截断为貌似完整的证据 |
| retrieval limit / maxEvidence | 5 / 6 | 1..20 的整数；资格 Research 样例固定 2 / 2 |
| 单个后端结果集 | 100 条 | 超限拒绝；合规结果按请求 limit 取前 N 条 |
| 检索问题 | 4000 字符 | 超限拒绝 |

模型 Provider 冻结源码不变；`.env` 构造器注入受限 fetch。该受限 fetch 面向有限非流式调用，不是 SSE 流式传输方案。直接使用冻结 Provider/Host、自定义传输或 callback 的调用方不自动获得该网络边界。

只接受 HTTP(S)，拒绝 URL userinfo/fragment；默认不允许非 loopback，远程必须显式 opt-in。禁止重定向不等于完整 SSRF/DNS rebinding 防护。没有跨进程任务锁、总工作流 SLA 或 exactly-once 外部副作用证明。

## 数据、兼容与异常

没有数据库 schema 迁移。既有 Session/Evidence/Execution 可继续读取；旧结果不自动重审或获得新版本背书。旧 RUN_R2_LIVE_PROBE 入口保留，但报告 schema 升为 ppl.execution-endpoint-probe/2，不再保证原宽松输出格式。

契约错误通过 contractError/contractIssues 记录；为兼容现有 UI，部分外层终态仍沿用 model-failed、blocked-analyst-model、blocked-judge-transport。判断具体原因应读取这些新增字段，而不是只看名称中的 transport。

## 验收与剩余工作

工程验收要求：四项旧错误可复现；修复回归通过；正常治理链未破坏；过度批准/过度拒绝 Judge 都不能通过对照；缺配置和空检索不能报通过；验收不改业务库；冻结文件身份一致；全新缓存离线安装和最终 ZIP 解压复验。

真实模型、Judge、Retrieval 身份与目标问题有效性、完整浏览器 HTTP E2E、Windows/macOS、多模型多样本评估尚待目标环境执行。R4b 的外部 Agent 框架适配尚未实现，不能把 R4a 已实现写成整个 R4 完成。
