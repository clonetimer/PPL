# R3 验收层级与遗留风险

## 不合并不同层级的“通过”

1. **产品 / HTTP 回归**：Node 真正监听 localhost，通过 fetch/http 请求实际 Gateway；模型结果来自有标识 fixture。此层验证接口、持久化和治理逻辑，不是模型能力。
2. **离线 Chromium DOM**：将源码中的 HTML/CSS/JS 载入内存，读模型来自真实服务 fixture 的快照；fetch 在测试中模拟。验证页面与请求构造，不包含 HTTP 导航、ESM 网络加载或浏览器 CSP 执行。
3. **完整浏览器 E2E**：提供脚本，本环境受 managed URL policy 拒绝，导航即 `ERR_BLOCKED_BY_ADMINISTRATOR`。记录为 BLOCKED，不合并进通过数，不更改管理策略以绕过限制。
4. **真实外部模型**：本轮未接入、未验收。既有 R2 live probe 可在操作者环境运行。

本轮结果和环境信息放在 `provenance/R3_EXECUTION_LEDGER.md`、`R3_PRODUCT_CHECKS.json`、`R3_DOM_REPORT.json`、`R3_BROWSER_BLOCKED_REPORT.json`。正式 ZIP 的解压后核验结果可另见交付的外部验证报告，避免将 ZIP 自身哈希写进内部文件形成循环。

## 本轮修复的接口问题

- R2 执行记录路由依赖活动执行器，移除模型配置便无法查看历史。改为按持久化 store 读取，保留会话 / run 归属检查。
- 单独领域状态可能遮盖最近一次执行的阻断结果。新只读投影同时显示 displayStatus 和 domain status，不修改原始记录。
- 旧路由过度接受尾部路径。新增精确长度匹配，避免 `/execute/extra` 等误触发。
- 增加受限 JSON object 解析及1MiB上限；畸形 / 超限请求提供明确400/413。
- Gateway 同 app/session 执行增加进程内互斥；不宣称跨进程或崩溃恢复 exactly-once。
- 页面 Tutor verifier 严格采用现有服务合法枚举；Life 页面确认、JSON 主张输入与工具查询不会绕过领域服务。
- 安装脚本统一 dev.4 和最低 Node22.16 声明；Windows batch 对 npm 使用 call。Windows 修订没有 Windows 实机验收。

## 风险与后续任务

| 优先级 | 风险 / 任务 | 依赖与验收方向 |
|---|---|---|
| P0 | 浏览器真实端到端未验证 | 在允许 localhost 的目标浏览器运行 r3-browser-smoke，检查模块 / CSP / 写入 / 下载 / 刷新 |
| P0 | 外部模型资格未验证 | 实际 Agent/Judge/检索服务；保留正反证、受控失败、延迟与费用记录 |
| P0 | 无用户认证与远程安全边界 | 在需要远程服务前落实身份、权限、密钥、审计访问控制，不能直接开放端口 |
| P0 | 外部副作用崩溃窗口 | 针对工具设计幂等键、恢复点、结果确认或补偿；不能用 UI 锁替代 |
| P1 | Agent框架适配 | 明确一个框架 / 工作流，适配器只用治理接口而不绕过 gate |
| P1 | 数据规模 | RecordStore SQL 查询、索引和分页改造；压测后才承诺容量 |
| P1 | 可访问性 / 兼容性 | Firefox/WebKit、目标 Windows/macOS、键盘 / 读屏测试 |
| P1 | 业务验证 | Tutor校准、Life外部账号连接、Character具体游戏接入，各领域分别立项 |

R3 不改变 R2 数据表结构；关闭旧服务、备份再指向旧库。只验证了测试数据的关闭 / 重开读取，不声称已验证未知用户数据的全部迁移路径。
