# PPL 1.0 产品架构（dev.3）

## 1. 定位

PPL 1.0 定位为 **Stateful AI Agent Governance Runtime**。R2 后的产品架构采用：

> **Shared Governance/Execution Kernel + Independent Verticals + Unified Gateway**

PPL 不再假设 Research、Tutor、Personal Assistant、Character/NPC 能共享同一个业务状态模型。它们只共享基础设施与治理机制。

## 2. 统一什么

```text
platform/core
├─ Record Store
├─ SQLite reference store
├─ SessionRepository
├─ AuditRepository
├─ EvidenceRepository
├─ revision / optimistic conflict
├─ idempotency / exactly-once event key
└─ HTTP utilities
```

这些能力不包含业务判断，因此可以跨场景复用。

R2 新增：

```text
platform/execution
├─ Host transport resilience
├─ OpenAI-compatible structured transport
├─ Retrieval adapters (HTTP JSON / SearXNG)
├─ Host-owned ToolExecutionLedger
├─ execution run repository
└─ live endpoint probe
```

执行基础设施可复用，但具体 Agent/Research pipeline 仍由各 Vertical 独立拥有。

## 3. 不统一什么

```text
product/agent-governance       Agent contract / authority / handoff / fidelity
product/research-governance    Claim / evidence / conflict / delivery binding
product/tutor-governance       Learner state / uncertainty / intervention verifier
product/life-governance        Durable preference / plan / realtime / risk
product/character-governance   Relationship state / deterministic transitions
```

每个 vertical 独立拥有 schema、状态机、API 与验收测试。一个场景的规则不能因为“代码复用方便”而自动获得另一个场景的语义。

## 4. 统一入口

`product/platform-gateway` 提供一个 HTTP 进程：

```text
/v1/agent/...
/v1/research/...
/v1/tutor/...
/v1/life/...
/v1/character/...
```

Gateway 统一部署面，但不合并业务状态；SQLite namespace 也按 vertical 隔离。

## 5. 与历史 Stable 的关系

`components/`、`dist/`、`rules/` 仍以 2026-08-27 Stable 基线为冻结语义来源。R1/R2 产品层通过发布件/公共接口或只读 bridge 使用它们，`verify-stable-component-identity` 确认 Stable 源码未被产品化改造隐式修改。
