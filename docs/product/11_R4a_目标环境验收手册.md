# R4a 目标环境验收手册

## 顺序

先 `bash VERIFY_PRODUCT.sh`，确认产品及冻结依赖的本机回归。然后配置 `.env` 并做 endpoints → agent → research/all；最后做目标浏览器的真实 HTTP 验收。各层结果单独保留，不能用前一层替代后一层。

## 配置与执行

安装后复制 `.env.execution.example` 为 `.env`，填写 Agent/Judge 的完整 chat/completions 地址、实际模型 ID，以及 HTTP JSON 或 SearXNG 检索地址。要求本机启动的服务由操作者确认，模型别名不能用来伪造身份独立。检索协议示例：HTTP POST `{query,limit,filters}`，响应 `{documents:[{id,title,url,text}]}`。SearXNG 使用 JSON 搜索结果片段，不声称取到了网页/论文全文。

```bash
npm run qualify:execution -- --scope endpoints --output local-results/endpoints.json
npm run qualify:execution -- --scope agent --output local-results/agent.json
npm run qualify:execution -- --scope all --question "填写你的实际研究问题" --output local-results/all.json
```

也可以 `--scope research` 跳过 Generic Agent。all/research 必须显式提供问题，或设置 `PPL_QUALIFY_QUESTION`；工具不替你选一个方便通过的业务问题。endpoints 默认包含检索；agent 不依赖检索，但当前执行依赖构造器仍要求 Agent 和 Judge 配置。

all 的流程：配置 → 身份声明检查 → Agent 随机 nonce → Judge 随机 nonce → 非空检索 → 合成正反证据 Agent 交接 → Judge 合理结论正对照 → Judge 矛盾结论负对照 → 实际问题的 Research 任务。

Judge 正负对照故意使用两条合成 benchmark 数据，一条 A 更快、一条 A 更慢。合理的 mixed 结论必须通过，声称两者均 A 更快必须拒绝。always-approve 与 always-reject 都不通过。协议错误、binding 不匹配不能当成“Judge 正确拒绝”。任一对照失败，Research 样例不再继续消耗模型调用。

## 报告解释

| 字段 | 如何解释 |
|---|---|
| scope / passed | 只对指定范围有效；endpoints 的 true 不等于任务成功 |
| checks[].status | passed / failed / skipped；依赖失败而未运行必须是 skipped |
| configuredEndpointTaskSmokePassed | 该次配置端点上的 Agent/Research 样例结果；endpoints 时为 null |
| judgeControlsPassed | 两个特定语义对照的结果，不是整体模型准确率 |
| evidenceMode | CLI 固定 configured-endpoints-unattested；内部 HTTP 替身测试标记 fixture-http |
| externalModelIdentityVerified | false；HTTP 响应不认证服务器实际运行的权重 |
| stableEligible | false；本工具不替代浏览器、安全、恢复和产品效果验收 |
| businessStoreTouched | false；使用隔离内存 Store，不打开正常 PPL_DB |

报告不保存原始问题、完整文档、模型正文或 API key，只保留问题/交付/证据哈希、标识及计数等诊断摘要。因此它不是完整审计日志，不足以单独重放全部业务证据；模型 ID 也仍可能敏感。报告文件不是签名证明，不可拿未经信任的报告文件当授权凭证。

## 退出码与排错

`0`：所选样例范围通过。`1`：请求失败、契约/nonce 不符、无资料、治理阻断或 Judge 对照不符。`2`：缺少/错误配置、缺研究问题、非法参数或无法写报告。

HTTP_TIMEOUT：检查模型吞吐、服务响应体是否结束，以及 PPL_HTTP_TIMEOUT_MS；不要先扩大超时掩盖死锁。
HTTP_BODY_TOO_LARGE / RETRIEVAL_DOCUMENT_TOO_LARGE：减少返回内容或明确调整资源预算，不自动截断证据。
RESPONSE_CONTRACT_INVALID：检查当前服务的结构化输出支持和具体 contractIssues；不要把字符串 false 转成布尔真。
MODEL_INDEPENDENCE_REQUIRED：同模型、同声明分组或未知身份被拒绝；改角色标签不构成修复。
COUNTER_EVIDENCE_ERASURE：这是治理阻断，报告应失败；先检查中间模型是否遗漏反证，不应通过调高 confidenceTolerance 绕开。

上游 HTTP 错误正文不直接回显，因此 HTTP 认证/服务内部问题需在你控制的服务端日志定位，不要把凭据粘贴进问题说明。

## 浏览器层

```bash
# 另行安装 Python Playwright 和受支持的 Chromium；它们不属于产品 npm 离线依赖
python tools/r3-browser-smoke.py --output local-results/r4-browser
```

该脚本启动独立 fixture 数据库和真实 localhost HTTP Gateway，检查浏览器操作与后端状态。即使它通过，也仍然是 fixture 模型而非外部真实模型。本构建环境导航返回 ERR_BLOCKED_BY_ADMINISTRATOR，属于 BLOCKED；没有修改或绕过浏览器管理策略。

`python tools/r3-dom-smoke.py --output local-results/r4-dom` 是离线 DOM/请求构造验证，fetch 由脚本模拟，不验证真实导航、原生模块加载或浏览器 CSP。不能用它替代上述 HTTP 浏览器层。

## 业务有效性晋级

通过一次完整样例只证明配置链可用。目标场景还需固定一组代表性问题和人工证据核对、保留失败样本，对比未治理基线的误交付/误阻断、延迟与调用成本；样本量和阈值需要业务方确定，本版不编造达标率。数据和结果集不能只保留通过案例。

R4b：在上述环境验收后单独实现一个选定外部 Agent 框架的适配与失败注入。不新增其他 Vertical。R5：认证、崩溃恢复等生产范围和目标平台明确后再决定 Stable 候选，不因版本号跳转自动晋级。
