# PPL 使用与部署总览

## 1. 选择你真正需要的层

- 只需要 Persona DSL：使用 `components/foundation/core`。
- 需要 Host-neutral session/state：增加 `runtime`。
- 需要 Tutor/Research/Life/Character 应用合同：增加 `profiles`。
- 需要治理多 Agent handoff 的 delegation authority、context projection、fidelity、canonical final delivery：增加 `governance/multi-agent-governance`；它不负责 orchestration。
- 需要真实 LLM Agent、tools、Judge、recoverable lifecycle：使用 `application/host`。
- 需要 Life service/mutation/risk boundary：增加 `application/life-binding`。
- 需要本地 OpenAI-compatible 模型：使用 `infrastructure/provider-local`。
- 需要 LM Studio 独立 Judge：使用 `infrastructure/judge-lmstudio-native`。
- 需要只读会话/证据 UI：使用 `application/observatory`。
- 需要从运行经验形成确定性规则：使用 `experience/rule-evolution`。

## 2. 当前随包提供的 npm artifacts

`dist/npm/` 当前只保留聚合包中明确提供且仍属当前 Stable 的安装件：

- `ppl-llm-host-adapter-0.1.13.tgz`
- `ppl-host-binding-life-0.1.1.tgz`
- `ppl-experience-rule-evolution-0.2.0.tgz`
- `ppl-multi-agent-governance-0.1.0.tgz`

其他组件在本聚合包中以源码为 canonical artifact；没有为了目录整齐伪造新的 npm 发布包。

## 3. Host 默认行为

Host 0.1.13 安装后 `experienceRuleMode` 仍为 `off`。要启用生产 fast-path，必须显式使用 `enforce` 且只允许 `status=validated` 的 rule。

## 5. Provider 0.1.0 包装说明

Local Provider 0.1.0 的原始 Stable `package.json` 仍声明 `ppl-llm-host-adapter: 0.1.0`。本次清理没有修改 Stable 产品内部 package metadata；在临时验证中把当前 Host 0.1.13 作为本地依赖链接后，Provider 测试为 16/16 PASS。若未来要重新发布 Provider npm artifact，应在 Provider 自己的版本主线中规范化该依赖，而不是在“文件清理”阶段静默改包。
