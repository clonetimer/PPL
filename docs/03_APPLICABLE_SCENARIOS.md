# PPL 适用场景说明

## 1. 适用性不是“能否写 Prompt”，而是“是否需要长期、可执行、可观察的行为状态”

| 场景 | 当前成熟度 | PPL 的主要价值 | 需要额外系统 |
|---|---|---|---|
| 角色扮演 / NPC | 高 | 身份、关系、私密/公开模式、情绪、行为规则 | LLM / 游戏 Host |
| 长期陪伴型助手 | 高-中 | 关系状态、互动边界、偏好、风格演化 | Memory / Safety |
| 个性化学习 Tutor | 中，建议进入 Profiles 主线 | 教学风格、掌握度状态、提示策略、鼓励/纠错模式 | 课程内容、评测、题库 |
| 科研助手 | 中，建议进入 Profiles 主线 | 研究角色、证据政策、质疑强度、用户研究状态 | 检索、文献、计算、引用系统 |
| 日常生活助手 | 中 | 偏好、习惯、服务风格、长期目标状态 | Calendar/Weather/Maps/高风险政策 |
| 项目/工作助手 | 中-高 | 工作角色、沟通模式、决策偏好、项目状态协议 | Git/Docs/Task/企业权限系统 |
| 游戏世界多 NPC | 中-高 | 每个角色的 Persona/关系图/状态机 | World state、多 Agent 调度 |
| 高风险医疗/法律/金融决策 | 不应单独依赖 PPL | 只可管理交互行为和用户偏好 | 专业规则、实时权威数据、合规系统 |

## 2. PPL 做什么

PPL 擅长的是：

- “这个 Agent 长期应该怎么表现”；
- “状态发生变化后行为应该如何变化”；
- “为什么这一轮改变了”；
- “哪些状态应该在成功后持久化”；
- “同一个角色/服务在不同关系、场景、任务阶段的行为差异”。

## 3. PPL 不做什么

PPL 当前不是：

- 知识库；
- RAG；
- Workflow engine；
- Tool router；
- 模型训练框架；
- 长期记忆数据库；
- 真值/事实验证系统；
- 多 Agent 调度器；
- 权限/安全策略引擎。

这些能力可以与 PPL 组合，但不应该被塞进 Core。

## 4. 从“角色扮演”扩展出去的关键

非娱乐场景不能只把 `character` 改名为 `assistant`。必须增加：

- Mission / 服务目标；
- User Model / 用户学习或需求状态；
- Task State / 当前任务阶段；
- Domain Policy / 证据、纠错、风险规则；
- Capability Requirements / 需要哪些工具；
- Evaluation / 是否真的帮助用户完成目标。

这些正是 `PPL Profiles` 新主线要解决的问题。
